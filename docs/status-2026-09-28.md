## O que é o produto

**VPM2 — Vídeos Para Minha Mãe.** CLI local (`vpm2 <url>`) que baixa um vídeo do
YouTube em inglês, transcreve, traduz para PT-BR com um LLM local (Ollama), sintetiza a
dublagem com clonagem de voz (Chatterbox) e remonta o vídeo com a trilha PT
sincronizada. Roda em WSL2 + RTX 5060 Ti (Blackwell, cu128). Caso de uso de referência:
vídeos do Bob Ross.

## Mapa da arquitetura

Pipeline em estágios com artefatos em disco (`work/<video-id>/`), retomada por
`is_done()`, `--force <stage>` para reprocessar (`vpm2/pipeline.py`), progresso com
`rich` (`vpm2/progress.py`, `NullReporter` nos testes), `free_cuda()` entre estágios de
GPU (`vpm2/gpu.py`).

| # | Estágio | Arquivo | Artefato | Motor |
|---|---|---|---|---|
| 01 | download | `stages/download.py` | `01_video.mp4`, `01_meta.json` | yt-dlp |
| 02 | extract_audio | `stages/extract_audio.py` | `02_audio.wav` (16 kHz mono) | ffmpeg |
| 03 | transcribe | `stages/transcribe.py` | `03_transcript.json` | `ASRBackend`: Parakeet TDT 0.6B v2 (NeMo, padrão, chunks de 120 s) ou faster-whisper large-v3 |
| 04 | translate | `stages/translate.py` | `04_translation.json` | Ollama `qwen3:8b`, 8 requisições em paralelo, `think: false` |
| 05 | synthesize | `stages/synthesize.py` | `05_clips/*.wav`, `05_clips.json` (`sample_rate`, `duration`), `ref_voice.wav` | Chatterbox Multilingual; modos `cloning` / `preset` / `profile`; cache entre vídeos em `work/_tts_cache`; retomável por clipe (escrita atômica) |
| 06 | assemble | `stages/assemble.py` | `06_audio_pt.wav`, `06_final.mp4` | `plan_timeline` + `atempo` paralelo (até 1.5x) + mux ffmpeg; trilha EN opcional (`--keep-original-audio`) |

Apoio: `cli.py` (argparse, `.env` via python-dotenv para `HF_TOKEN`, preflight,
`url.py` para sanear URL e rejeitar canal/playlist), `preflight.py` (ffmpeg, Ollama,
modelo), `artifacts.py` (validadores), `voices/profile.py` (perfis
`voices/<id>/ref.wav + profile.json`, `cache_key`), `voice_sample.py`, `timeline.py`,
`translate_prompt.py`, `scripts/check_parakeet.py` (verificação manual em GPU).

## Riscos

1. `master` local divergente (ver o aviso no topo). Rodar `uv` no Windows dentro do
   checkout principal também tenta apagar o `.venv` do WSL (aconteceu neste
   levantamento; o `.venv` foi recriado no WSL). Os worktrees do harness têm `.venv`
   próprio.
2. `uv sync` puxa torch cu128 + `nemo_toolkit[asr]` + `chatterbox-tts` (vários GB; NeMo
   no Windows é incerto). Por isso a política do harness usa ambiente leve efêmero
   (`uv run --no-project --with ...`). Uma dependência leve nova no `pyproject.toml`
   exige incluir `--with <pacote>` no `requiredChecks`, até a #8 (extra `gpu`) entrar e
   o check poder virar `uv sync` + `uv run pytest -q`.
3. Stack de GPU nunca validada de forma registrada; só o Paulo pode fazer isso (#21).
